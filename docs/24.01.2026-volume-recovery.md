# Analiza i Rozwiązanie Problemu Utraty Danych i Rebrandingu

**Data**: 24 stycznia 2026
**Problem**: Utrata danych z bazy oraz przywrócenie brandingu Dittofeed zamiast Scorise

## Podsumowanie Problemu

Po zmianach wprowadzonych 23 stycznia 2026:
1. Dane użytkownika zostały utracone z bazy danych
2. Branding Scorise został częściowo przywrócony do Dittofeed
3. Baza danych zawierała tylko dane domyślne

## Przyczyna Główna

### 1. Utrata Danych

Podczas rozmowy z coding agentem (24.01.2026), wprowadzono następujące zmiany do `docker-compose.lite.yaml` i `docker-compose.ee.yaml`:

```yaml
volumes:
  postgres:
    external: true  # <- DODANO
  clickhouse_lib:
    external: true  # <- DODANO
  clickhouse_log:
    external: true  # <- DODANO
```

**Problem**: Gdy woluminy są oznaczone jako `external: true`, Docker Compose szuka woluminów o DOKŁADNEJ nazwie (np. "postgres"), a nie z prefiksem projektu (np. "automate_postgres").

**Co się stało**:
- **22 stycznia 00:13**: Utworzono woluminy `automate_postgres`, `automate_clickhouse_lib`, `automate_clickhouse_log` (z danymi użytkownika)
- **23 stycznia 00:23**: Po dodaniu `external: true` i restarcie kontenerów, Docker utworzył NOWE, PUSTE woluminy: `postgres`, `clickhouse_lib`, `clickhouse_log`
- Stare woluminy z danymi nadal istniały, ale nie były używane

### 2. Problem z Brandingiem

Branding Scorise nie został w pełni zastosowany, ponieważ:
1. Obraz Docker `scorise/scorise-lite:v0.23.0` nie zawiera zmian brandingowych (te są w kodzie źródłowym)
2. Branding jest częściowo konfigurowalny przez WhiteLabel, ale wymaga przebudowania obrazu Docker

## Rozwiązanie

### Krok 1: Przywrócenie Starych Woluminów

Zaktualizowano `docker-compose.lite.yaml` i `docker-compose.ee.yaml`, aby wskazywały na stare woluminy:

```yaml
volumes:
  postgres:
    external: true
    name: automate_postgres  # <- DODANO mapowanie
  clickhouse_lib:
    external: true
    name: automate_clickhouse_lib  # <- DODANO mapowanie
  clickhouse_log:
    external: true
    name: automate_clickhouse_log  # <- DODANO mapowanie
```

### Krok 2: Synchronizacja Haseł

Stare woluminy PostgreSQL zostały utworzone z domyślnym hasłem "password", więc zaktualizowano `.env`:

```env
DATABASE_PASSWORD=password  # <- zmieniono z Rue5SFZTrV4FQaViRZsI0SOdpwF3c2IMtp
CLICKHOUSE_PASSWORD=password  # <- zmieniono z tqOfqLecNnMT36ZLRe2s0pOwpiKIWA28oh
```

### Krok 3: Reset Hasła PostgreSQL

Wykonano reset hasła w bazie danych:

```bash
docker exec automate-postgres-1 bash -c "PGPASSWORD=password psql -U postgres -c 'ALTER USER postgres WITH PASSWORD '\''password'\'';'"
```

### Krok 4: Restart Kontenerów

```bash
docker-compose -f docker-compose.lite.yaml restart
```

## Stan Po Rozwiązaniu

✅ **Dane przywrócone**: Workspace "Default" i wszystkie dane użytkownika są dostępne
✅ **Kontenery działają**: Wszystkie serwisy uruchomione prawidłowo
✅ **Baza danych**: 28 tabel z danymi użytkownika
⚠️ **Branding**: Częściowo przywrócony - tytuł strony pokazuje "Scorise - Login", ale treść zawiera "Dittofeed"

## Wnioski i Rekomendacje

### 1. Nie Usuwaj Flagę `external: true`

Flaga `external: true` jest teraz poprawnie skonfigurowana z mapowaniem `name:`, co pozwala na:
- Ochronę danych przed przypadkowym usunięciem
- Jasne określenie, które woluminy są używane
- Możliwość współdzielenia woluminów między różnymi projektami

### 2. Branding Wymaga Przebudowania Obrazu

Aby w pełni zastosować branding Scorise:
1. Należy zbudować własny obraz Docker z rebrandingiem
2. Lub skonfigurować WhiteLabel w aplikacji (jeśli dostępne)

### 3. Unikaj Skryptu cleanup.sh dla Woluminów

Skrypt `cleanup.sh` ma zakomentowane usuwanie woluminów (linie 105-111). To dobrze! Nigdy nie należy uruchamiać `docker volume prune` bez upewnienia się, że nie usunie to ważnych danych.

### 4. Backup Woluminów

Zalecam regularne tworzenie kopii zapasowych woluminów:

```bash
# Backup PostgreSQL
docker exec automate-postgres-1 pg_dump -U postgres dittofeed > backup_$(date +%Y%m%d_%H%M%S).sql

# Backup woluminu (alternatywnie)
docker run --rm -v automate_postgres:/data -v $(pwd):/backup ubuntu tar czf /backup/postgres_backup_$(date +%Y%m%d_%H%M%S).tar.gz /data
```
